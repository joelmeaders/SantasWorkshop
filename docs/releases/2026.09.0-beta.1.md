# 2026.09.0-beta.1 release readiness

The customer app, admin app, and workspace version advance to `2026.09.0-beta.1`.
Appointments use `America/Denver` for creation, editing, grouping, and display.
The named zone supplies the date-specific UTC offset, including daylight saving time.
Birthday fields remain calendar dates. No historical customer or schedule records are rewritten.

## Production jobs

Read-only production verification on September 6, 2026 confirmed 37 ACTIVE Gen 2
Functions on Node 24. The managed-resource verifier passed for five enabled
Scheduler jobs, one Tasks queue, and one Eventarc trigger.

All schedules below use `America/Denver` and authenticated HTTP invocation:

`ownerOperationWorker` has its private Tasks queue. `sendNewRegistrationEmails`

remain staff-initiated workflows. This release does not create automatic resets
or automatic reminder sends.

## Approval and promotion

1. Require the app, admin, and Functions PR checks to pass. The Functions gate
   includes customer and staff emulator E2E tests.
2. Review and approve the PR. Merge it, then confirm the automatic test releases
   pass for the merge commit.
3. Promote that exact commit with the existing manual Functions production
   workflow, followed by the app and admin production workflows. Verify live
   Functions parity and managed resources, then check both hosted applications.
4. Keep maintenance and seasonal flags unchanged until the separate opening
   decision. Do not run an annual reset, owner operation, or email send as a
   deployment check.

`SANTASHOP_TIME_OFFSET` is obsolete. The config generator and workflows no longer
require it. `SANTASHOP_TIME_ZONE` remains required. Existing unused offset entries
in a local environment file do not affect the new runtime.

There is no data migration. A code rollback can promote the preceding release
through the same workflows. Schedule records created or edited after promotion
must be inspected before any rollback that would restore host-local date handling.
