# 2026.09.0-beta.2 release note

The customer and staff workflows keep each registration's confirmation code and
QR artifact stable across cancellation and later re-registration. The code is
blocked for check-in while the registration is canceled. After re-registration,
the same code and QR artifact become usable again.

The normal customer and admin test gates now run the complete Storybook
validation. The separate Storybook pull-request workflow continues to compare
the reviewed Windows visual baselines.

Unit, emulator-integration, and browser tests now use stronger assertions,
better isolation, deterministic season setup, and broader workflow triggers.
Customer and admin components use Angular signals for local UI state while
keeping their existing observable service boundaries.

Cancellation still records a dedicated cancellation event and sends the
cancellation message. The cancellation message does not contain an active QR
ticket.

## Documentation scope

- Business, functional, and non-functional requirements now define stable QR
  identity across cancellation.
- The integrated test matrix checks that cancellation blocks the code and that
  later re-registration restores the same code.
- Hosted-QA notes and package changelogs use the current stable-QR policy.

This note describes the intended beta behavior. It does not claim a production
deployment or hosted validation of this change.
