# 2026.09.0-beta.3 release note

Public customer and staff controls now use one unconditional Remote Config JSON
parameter, shared with backend operation checks. Owners can edit switches and
bilingual messages in App settings. Publishing validates every field and uses
ETags to prevent overwriting another owner's changes. Unsaved edits survive
conflicts and failed publication.

Both apps retain valid cached settings or validated release defaults during
outages. Real-time updates activate immediately. Backend checks use a ten-second
on-demand cache with background refresh. Configuration checks are no longer
atomic with Firestore transactions: in-flight work may finish after publication,
and outages can extend stale values.

This release also includes the pending friendly update prompts, reload recovery,
service-worker caching, and browser QA improvements. Firestore Lite remains in
the customer startup graph.

Publish the reviewed target configuration before deploying dependent code.
Provision the dedicated service accounts and resolve the template-read quota
gate. Leave the legacy Firestore document intact; older app versions must
upgrade to receive settings changes.

See [migration and release steps](../remote-config.md) and
[validation evidence](../remote-config-validation.md). Local checks are not
deployed acceptance. Production promotion requires separate approval.
