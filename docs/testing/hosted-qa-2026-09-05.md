## Confirmed issues addressed

- Queue every registration email request as a new document. Reject obsolete
  registration payloads and guard delivery bookkeeping against concurrent
  changes. Manual resends and reminders read current contact data in the
  transaction that creates the queue entry.
- Distinguish committed cancellation from a later QR-finalization failure.
- Refresh authenticated customer state after profile changes.
- Show staff access denial and prevent duplicate sign-in submissions.
- Preserve calendar birthdays, including existing UTC-midnight values, and
  require a new toy selection when an infant becomes an older child.
- Make custom referral Save visible, validate its value, and make Cancel discard
  the selection.
- Preserve staff preregistration drafts after callable failure and suppress the
  false success alert.
- Record the blocked scan when a competing check-in transaction loses at commit
  with an already-exists error. Read transaction documents in one request to avoid
  an intermittent invalid/closed transaction failure found by emulator tests.
- Patch schedule fields independently so date/time saves cannot overwrite a
  concurrent capacity or enabled-state change.
- Render template previews without dynamic code execution and enforce the
  supported template syntax consistently.
- Store complete local dates in check-in statistics so activity from different
  months does not merge. Existing monthless event buckets retain December
  interpretation.
- Show schedule capacity when live slots exist but the seasonal aggregate does
  not. Use nightly registration data as the missing-aggregate fallback.
- Localize customer dates, the appointment status message, and the account/help
  menu label. Correct email timing copy and small labels, plural forms, and
  accessible controls found during the walkthrough.

## Limits and required follow-up

- Camera scanning could not be exercised because camera access was unavailable
  in the browser session. Manual code entry and scanner result handling were
  exercised.
- Bulk owner operations were previewed only. Annual deletion, exports, bulk
  reminders, repair, and rebuild were not executed against existing test data.
- Reservation aggregates follow the configured seasonal schedule. Their absence
  in September is expected; the misleading report state is fixed separately.
- SES cannot recall an email already accepted while a registration changes.
  The fix checks state before the send and guards later bookkeeping, but does
  not promise atomicity across Firestore and SES.
- Queue records without request or appointment identity fields cannot receive
  every freshness check available to new queue entries.
- Existing monthless check-in aggregates cannot identify non-December activity.
  Rebuild the test year's statistics from raw check-ins after deployment when
  checking the date correction against previously recorded activity.
- After merge and test deployment, repeat the failed hosted cases, especially
  resend/change confirmation delivery, profile email-to-password change,
  referral cancel/save, birthday edits, schedule edits, Spanish dates, and
  template preview. Local validation does not replace that deployment check.
